## 三、"不写 C#"带来的问题，以及怎么补

这是本项目最大的协作风险，值得说清楚。

### 问题

- 你看不出代码哪里错了，只能告诉我"它没工作"
- 出错时你无法定位，反馈信息量低
- 每一轮试错的成本比正常开发高

### 缓解措施（这些是我的责任，不是你的）

**1. 快照文件 —— 最关键的一条**

L2 层的城市状态 JSON 会 dump 到本地文件。你只要把这个文件贴给我，我就能在没有游戏的机器上复现推理过程、迭代逻辑。

这把大部分调试从"你在游戏里试"转移到"我在本地跑"，是整个协作模式的支点。所以**快照 dump 要在第一个里程碑就做好**，优先级高于任何功能。

**2. 一键脚本**

你不需要理解 MSBuild。`scripts/` 下会提供：

| 脚本 | 作用 |
|---|---|
| `build.ps1` | 编译 + 部署到本地 Mods 目录 |
| `collect.ps1` | 打包日志 + 快照，生成一个可直接发我的 zip |
| `clean.ps1` | 清理构建产物，排除"上次的残留导致的怪问题" |

**3. 日志自解释**

Mod 的日志不只打"发生了什么"，还打"这说明什么"。例如：

```
[UrbanBrain] L1 采集: 扫描到 1247 条车道, 其中 89 条有 LaneFlow 组件
[UrbanBrain] ⚠ 预期至少 200 条有 LaneFlow —— 可能是 ECS 查询过滤条件写错了
```

你不用懂代码，把带 ⚠ 的行贴给我即可。

**4. 每个里程碑有视觉验收标准**

不说"实现采集层"，而说"**你应该在屏幕右上角看到一个数字，选中不同路口时它会变**"。你只要判断看到没看到。

## 四、反馈协议

出问题时，按这个顺序给我信息（有几条给几条）：

1. **你做了什么** —— 点了哪里、走到哪一步
2. **期望 vs 实际** —— 应该看到 X，实际看到 Y / 什么都没有 / 游戏崩了
3. **`collect.ps1` 生成的 zip**，或至少：
   - 编译报错的完整输出（红色的那些）
   - 游戏日志目录下的相关文件
     `%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\Logs\`
     *(具体文件名待第一次实测确认)*

**别帮我筛信息。** 你判断"这条应该没关系"的日志，往往正是关键的那条。全量贴过来，筛选是我的活。

## 五、API key 的安全与成本约定

### 安全

- key **绝不进仓库**。`.gitignore` 已排除 `*.key` / `.env` / `*secret*` 等
- key 存在游戏的 mod 设置里（用户数据目录），跟着你的机器走
- 发布到 Paradox Mods 时，必须在 mod 描述里**明确写清楚会把哪些数据发到哪个服务商**。这是底线，不是可选项

### 成本

每次诊断都是一次 API 调用，要花钱。设计上必须控制：

- 诊断**由玩家主动触发**，不做后台轮询
- 送给模型的是 L2 的**结构化摘要**，不是原始数据全量
- 相同城市状态**缓存结果**，不重复调用

具体的模型选型和成本估算，等推理层动工时再定。

### 一个必须守住的产品原则

**LLM 说错比不说更糟。** 诊断界面上，AI 的结论必须和支撑它的原始数据并排展示，让你能自己验证。宁可显示"数据不足，无法判断"，也不要编一个听起来合理的因果链。

## 六、里程碑

### M0 — 跑通管线（不碰 AI）

**目标**：证明"编译 → 部署 → 游戏加载 → 读到数据 → 显示出来"这条链路是通的。

**验收**：进游戏后，选中一个路口，屏幕上出现一个面板，显示该路口的实时车流数字，切换路口数字会变。

这一步是整个项目风险最高的一段——一旦通了，后面都是在已验证的地基上加东西。

### M1 — 快照导出

**目标**：把城市状态导出成结构化 JSON 文件。

**验收**：游戏里点一个按钮，生成一个 json 文件，你能把它发给我。

**做完这一步，我才真正能独立工作。**

### M2 — 因果链（纯规则）

**目标**：不接 AI，用写死的规则跑通一条完整因果链的展示。

**验收**：面板上显示出类似"商业区货运不足 ← 卡车绕行 ← 主干道饱和"的链条。

### M3 — 接入 LLM

在前面全部验证过的基础上，把规则引擎换成/补充为 API 调用。
