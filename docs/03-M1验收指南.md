# M1 验收指南：信号写入验证

目标：验证我们**能不能安全地写入路口信号状态并被游戏采纳**。

功能上毫无实用价值（把全城红绿灯冻住或者疯狂闪烁），但它一次性验证了整条链最危险的部分：
编译 → 部署 → 模组加载 → 接管原版系统 → 写入生效。

---

## 一、构建

```powershell
.\scripts\build.ps1
```

脚本会先检查 toolchain 装好没，再编译，成功的话产物自动进
`%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\Mods`。

---

## 二、测试步骤

1. 启动游戏，**载入一个有红绿灯路口的存档**（新城市没路口测不了）
2. 打开 Options，左侧应该能看到 **Urban Brain**
3. 进去看「当前状态」区域：
   - 「接管模式」应显示 *未接管*
   - 「已接管路口」应显示一个数字
4. 把镜头对准一个红绿灯路口，**取消暂停让游戏跑起来**
5. 点「**接管并冻结信号**」
6. 盯着路口看 10 秒

---

## 三、结果对照表

| 你看到的 | 说明什么 | 你要做的 |
|---|---|---|
| **信号灯不再变化，卡在当前相位** | ✅ **M1 通过。** 写入生效了 | 告诉我，然后点「释放所有路口」恢复 |
| 信号灯照常变化，毫无反应 | 写入没被采纳，或 `m_Timer` 不是我以为的用法 | 跑 `collect.ps1` 把日志发我 |
| 「已接管路口」显示 *接管通道不可用* | 游戏更新改了原版字段名 | 发日志，我重新确认字段名 |
| 「已接管路口」一直是 0 | 没找到红绿灯实体 | 确认存档里真的有信号灯路口，再发日志 |
| Options 里根本没有 Urban Brain | 模组没加载 | 发日志 |
| 游戏崩溃 | 需要看崩溃点 | 发日志 |

如果「冻结」有效，可以再点「**接管并加速切换**」，预期是信号疯狂闪烁。
两个模式效果都对，说明我们对信号的控制是**双向可调**的，不是碰巧。

**测完记得点「释放所有路口」。** 忘了也没关系——接管标记故意没有写进存档，重新读档就自动恢复了。

## 四、收集日志

```powershell
.\scripts\collect.ps1
```

生成的 zip 直接发回。

**不要自己筛选日志内容。** 你觉得"这条应该没关系"的行，往往正是关键那条。

---

## 五、日志里会有什么

正常加载时应该能看到：

```
========== Urban Brain 开始加载 ==========
模组文件位置：...
已改写原版 TrafficLightSystem.m_TrafficLightQuery，接管通道就绪。
========== Urban Brain 加载完成（接管能力：可用）==========
```

接管运行时，每 256 帧会打一条采样：

```
[接管中] 模式=Freeze 路口数=37 | 样本 entity=12345 state=1->1 timer=43->0 group=2/4 next=3
```

这行信息量最大 —— 即使你在画面上看不出变化，`timer=43->0` 也能告诉我写入到底有没有落下去、
原版有没有又给改回来。

带 `⚠` 的行是我预埋的异常提示，**优先把这些行发我**。

---

## 六、已知风险

这批代码有两处是猜的，可能导致失败：

1. **原版私有字段名 `m_TrafficLightQuery`** —— 来自 TrafficLightsEnhancement 的源码，
   它是活跃维护的项目，可信度较高，但不能保证和你的游戏版本一致。
   猜错的表现是「接管通道不可用」，代码里已做降级，不会崩。

2. **`m_Timer` 的语义** —— 组件定义确认它存在且是 byte，但"压到 0 会冻结相位"是推断，
   不是从原版代码读出来的。猜错的表现是画面无变化，但采样日志仍会给出线索。

第一次编译不过也属于正常，把完整报错发我就行。
