## 零、新会话的接手流程

1. 先读本文件的**第一节（阻断级）**，对着反编译核对
2. 编译：`.\scripts\build.ps1`
3. 编译过了再看**第二节（运行级）**
4. 不要一上来就追行为问题 —— 先确认它能加载

**风险性质变了。** 两个模组各自都在真实游戏里跑通过，所以
「游戏 API 用错」的风险很低；真正的风险集中在**合并这件事本身**：
程序集引用、资源路径、入口改造、两者共存。

## 一、阻断级：猜错会编译失败

### 1.1 游戏程序集引用是否齐全 🔴 最可能出问题

`src/UrbanBrain.csproj` 里的 `<Reference>` 列表取自两个模组 csproj 的**并集**。

| 来源 | 引用数 |
|---|---|
| Traffic 原 csproj | 21 |
| TLE 原 csproj | 19 |
| 本项目并集 | 24 |

**猜错的表现**：`CS0246 找不到类型或命名空间名 XXX`。

**核对方法**：看报错缺哪个类型，去
`Cities Skylines II\Cities2_Data\Managed\` 找包含它的 dll，
在 csproj 的 ItemGroup 里补一行。

另外 `mscorlib` 这条是 Traffic 特有的，若 Mod.props 已隐式引入可能报重复定义，
报错就删掉它。

### 1.2 `Localization.LoadLocales` 的签名改动

`src/Traffic/Localization.cs` 中该方法原型是 `(Mod mod, float)`，
我改成了 `(Game.Modding.IMod mod, float)`。

原因：它内部要调 `modManager.TryGetExecutableAsset(mod, ...)`，
只有**真正注册到游戏里的 IMod 实例**才取得到资源路径。
并入后 `Traffic.Mod` 不再是 IMod，必须传 `UrbanBrain.Mod`。

**猜错的表现**：编译报参数类型不匹配，或运行时找不到 Localization 目录。

### 1.3 TLE `Settings` 构造传入 owner

`src/TLE/Mod.cs` 里 `new Settings(owner)`，owner 是 `UrbanBrain.Mod`。
`Settings` 构造函数内部会调 `RegisterInOptionsUI()` 和 `AssetDatabase.global.LoadSettings`。

**待确认**：同一个程序集注册**两个** ModSetting（Traffic 的 + TLE 的）是否被允许。

**猜错的表现**：编译能过，但游戏启动时抛异常，或只有一个设置页出现。
若不允许，需要把两者合并成一个 ModSetting 类。

### 1.4 C# 语言特性

TLE 用了集合表达式 `[...]`（C# 12）和 `CallerArgumentExpression`。
csproj 已设 `<LangVersion>12.0</LangVersion>`。

**猜错的表现**：`CS8652 该功能是预览版功能`。

### 1.5 已改动的源文件清单

合并时动过的地方，编译出问题优先查这几处：

| 文件 | 改动 |
|---|---|
| `src/Mod.cs` | 全新写的统一入口 |
| `src/Traffic/Mod.cs` | 去掉 IMod，OnLoad 加 owner 参数，删掉外部 TLE 检测 |
| `src/TLE/Mod.cs` | 同上；`m_Id` 改成常量；`m_InformationalVersion` 取自 `UrbanBrain.Mod.kVersion` |
| `src/Traffic/Localization.cs` | LoadLocales 签名改 IMod |
| `src/TLE/Settings.cs` | 删 `m_LaneSystemVersion`；`m_TleVersion` 去掉 `Substring(0,20)`（短版本号会越界） |
| `src/TLE/Utils/LocalisationUtils.cs` | 删两条 LaneSystem 版本条目；设置页标题中文化 |
| `src/TLE/Systems/UI/UISystem.UIBIndings.cs` | 删车道方向工具菜单项与其 binding |

## 二、运行级：编译过了但可能不对

### 2.1 UI 产物扩展名 `.mjs` 🟡

`ui/webpack.config.js` 里 `filename: "[name].mjs"`。

**依据不足**：Traffic 与 TLE 原工程都没显式指定 filename，用的是 webpack 默认的 `.js`。
我改成 `.mjs` 是按 CS2 UI 模组的通行约定，**没有实证**。

**猜错的表现**：游戏能进，C# 功能正常，但界面完全不出现，日志也不报错。

**核对方法**：看 `Mods\UrbanBrain\` 下的产物文件名；
若界面不出，把 filename 改回 `[name].js` 再试一次。这是一行改动。

### 2.2 `mod.json` 的 id 与 AssemblyName 🟡

`ui/mod.json` 的 id 是 `UrbanBrain`，与 `AssemblyName` 一致。
webpack 用它作为产物文件名。**是否必须一致未经确认。**

### 2.3 TLE 嵌入资源的 LogicalName 是否生效 🟡

TLE 按固定名字查资源：
`"C2VM.TrafficLightsEnhancement.Resources.Localisations." + locale + ".json"`

并入后默认资源名会变成 `UrbanBrain.TLE.Resources....`，
所以 csproj 用 `<LogicalName>` 把名字固定回原样。

**猜错的表现**：信号面板文字全是 key 本身（如显示 `SplitPhasing` 而不是「分向放行」），
或图标不显示。功能仍可用。

**核对方法**：日志里搜 TLE 的资源加载报错；或直接看面板文字。

### 2.4 Traffic 的 Localization 目录部署位置 🟡

Traffic 运行时从「dll 所在目录\Localization\」读 json。
csproj 用 `<Link>Localization\%(Filename)%(Extension)</Link>` 把它们复制过去。

**猜错的表现**：日志出现 `Locale directory not found!`，车道工具界面显示英文。

### 2.5 两模块的键位绑定是否撞键 🟢 已静态排除

查过两边的绑定声明，结论是不冲突：

- Traffic：`Ctrl+R` 车道连接工具、`Ctrl+T` 优先级工具、
  `Ctrl+1~4` 与 `Delete`。后面这些都带
  `ModKeyUsages.LaneConnectorToolActive` / `PrioritiesToolActive` 限定，
  只在对应工具激活时生效，而两个工具互斥
- TLE：只有一个面板开关键，默认值是 `BindingKeyboard.None`（未绑定）

所以 `Ctrl+1~4` 在两个工具下含义不同但不会互相触发，TLE 也不占键。

仍需实机确认的是：这些键有没有和**游戏原版**的绑定撞上。

### 2.6 两模块接管的系统是否真的互不干扰 🔴 最需要实机确认

设计假设：

- Traffic 禁用 `Game.Net.LaneSystem`，插入 `TrafficLaneSystem` 替代
- TLE 改写 `Game.Simulation.TrafficLightSystem` 的查询条件，插在其前

这两者操作的是不同系统，理论上不冲突。**但这是推断，不是实测。**

值得注意的反证：Traffic 原本专门写了检测外部 TLE 并禁用其 LaneSystem 的代码
（`TLECompatibilityFix`）。那处理的是 TLE 的 `CommonLibraries.LaneSystem`
（车道方向模块），而我们**没有并入那个模块**，所以理论上不需要。

**猜错的表现**：路口车道错乱、信号灯不亮、存档载入后路口重置。

### 2.7 `TrafficLaneSystem` 对游戏版本的依赖 🔴

`src/Traffic/Systems/Traffic_LaneSystem.cs` 是 9,659 行，
是游戏原版 `LaneSystem` 的**反编译改造版**。

它假定了游戏内部实现的诸多细节。游戏一旦大更新，这里是最先失效的地方，
且失效方式往往不是编译错误，而是**车道生成异常**。

Traffic 上游版本对应的游戏版本，见 `_reference/Traffic/Code/Changelog.md`。

## 三、已知的设计取舍（不是 bug）

| 取舍 | 原因 |
|---|---|
| 不并入 `C2VM.CommonLibraries.LaneSystem` | 它的车道转向限制与 Traffic 的车道连接器功能重叠，且两者都要改 LaneSystem，必然冲突。转向控制统一走车道连接器 |
| `TLEDataMigrationSystem` 保留但未挂载 | 它用于从外部 TLE 迁移车道方向数据。我们没并入那个模块，无数据可迁。文件保留（反射访问，不产生编译依赖） |
| 两个设置页并存 | 合并成一个需要重写两边全部设置项与键位绑定，风险高于收益。已通过统一命名让它们看起来属于同一模组 |
| 保留各自原命名空间 | 128 个文件全局改名风险高、收益低，且便于日后与上游对比 |
