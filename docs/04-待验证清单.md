# 待验证清单

**这份文档是给「有游戏的那台机器上的新会话」用的。**

代码是在没有游戏、没有反编译程序集的机器上写的，所有游戏 API 都来自两个间接来源：

1. [cs2-ecs-explorer](https://github.com/Captain-Of-Coit/cs2-ecs-explorer) 的组件数据集（**2023 年游戏发布初期版本**）
2. TrafficLightsEnhancement / InfoLoom / Traffic 的源码（活跃维护，可信度较高）

**没有任何一行在真实游戏里跑过。** 下面按风险排序列出所有猜测点。

---

## 零、新会话的接手流程

1. 确认 toolchain：游戏 Options → Modding 全绿勾
2. 用 ILSpy 打开 `%CSII_INSTALLATIONPATH%\Cities2_Data\Managed\Game.dll`
3. **先核对第一节的「阻断级」条目**，改掉对不上的
4. 跑 `.\scripts\build.ps1`，按编译错误逐个修
5. 编译通过后，按 [03-M1验收指南](03-M1验收指南.md) 做探针验证
6. 探针通过后，再验证第二节的「行为级」条目

顺序很重要：先让它编译，再让它正确。不要一开始就追行为问题。

## 一、阻断级：猜错会编译失败

### 1.1 原版私有字段名 `m_TrafficLightQuery`

**位置**：[src/Mod.cs](../src/Mod.cs) `kVanillaQueryField`

**猜了什么**：`Game.Simulation.TrafficLightSystem` 内部持有路口查询的私有字段叫这个名字。

**依据**：TLE 的 `Mod.cs` 里就是这么用的，且 TLE 在活跃维护。

**怎么核对**：ILSpy 打开 `Game.Simulation.TrafficLightSystem`，看私有 `EntityQuery` 字段的实际名字。

**猜错的表现**：不会编译失败（走反射），设置页显示「接管通道不可用」，日志有 ⚠。代码已做降级，不会崩。

> 附带问题：`Game.Net.TrafficLightInitializationSystem` 我**没有**接管。它负责初始化信号组，可能会重置我们写的 `LaneSignal`。TLE 连它一起接管了（字段名 `m_TrafficLightsQuery`，注意比上面多个 s）。如果发现相位方案被莫名重置，八成是这里。

### 1.2 程序集引用名

**位置**：[src/UrbanBrain.csproj](../src/UrbanBrain.csproj)

**猜了什么**：`Reference Include` 的那一串名字（`Colossal.UI.Binding`、`Newtonsoft.Json` 等）在当前游戏版本里都存在。

**依据**：抄自 TLE 和 InfoLoom 的 csproj。

**怎么核对**：直接看 `Cities2_Data\Managed\` 目录里的 DLL 文件名。

**猜错的表现**：编译报 `找不到程序集` 或 `未能找到类型`。删掉用不到的 Reference 即可（目前实际用到的是 Game、Colossal.Core、Colossal.Logging、Colossal.IO.AssetDatabase、Colossal.Localization、Newtonsoft.Json、Unity.Entities、Unity.Collections、Unity.Mathematics、UnityEngine.CoreModule）。

### 1.3 `ComponentLookup.Update()` 的签名

**位置**：[src/Systems/IntersectionScanSystem.cs](../src/Systems/IntersectionScanSystem.cs) `BuildScanner()`

**猜了什么**：`m_SubLane.Update(this)` —— 传 SystemBase 的重载存在。

**风险**：Unity Entities 里常见的是 `Update(ref SystemState)`。TLE 用的是 `Update(ref state)` 形式（在 job struct 里）。

**猜错的表现**：编译报没有匹配的重载。改成 `Update(ref CheckedStateRef)` 试试。

**这一条我认为最可能出错**，优先看。

### 1.4 `EdgeGeometry` 的嵌套结构

**位置**：[src/Utils/IntersectionScanner.cs](../src/Utils/IntersectionScanner.cs) `GetEdgePosition()`

**猜了什么**：`geo.m_Start.m_Left.a` 和 `geo.m_End.m_Left.d` —— Segment 里有 `m_Left`/`m_Right` 两条贝塞尔曲线，`.a` 是起点、`.d` 是终点。

**依据**：逐行抄自 TLE `NodeUtils.GetEdgePosition`。

**猜错的表现**：编译报字段不存在。

### 1.5 `ISerializable` 的 `writer.Write()` 重载

**位置**：[src/Components/SignalPlan.cs](../src/Components/SignalPlan.cs)

**猜了什么**：`IWriter` 支持 `ushort` / `uint` / `int` / `float` / `bool` / `Entity` 的 Write 重载。

**依据**：TLE 的 `CustomPhaseData` 写了 ushort/float3/float/int/uint，`CustomLaneDirection` 写了 Entity 和 bool。所以这些应该都有。

**猜错的表现**：编译报没有匹配重载。把对应字段换成有重载的类型（例如 bool 存成 byte）。

### 1.6 设置界面特性

**位置**：[src/Setting.cs](../src/Setting.cs)

**猜了什么**：`SettingsUIButton` / `SettingsUISection` / `SettingsUIHidden` / `SettingsUIDisableByCondition` / `SettingsUIGroupOrder` / `SettingsUIShowGroupName` 都存在且签名如此。

**依据**：TLE 的 `Settings.cs` 全用了这些。

**注意**：`SettingsUIShowGroupName` 我传了参数（`[SettingsUIShowGroupName(kGroupStatus, ...)]`），InfoLoom 是这么用的但 TLE 用的是无参形式。如果报错，改成无参。

### 1.7 枚举成员

以下枚举成员来自参考源码的实际用法，**可信度较高**，但仍需确认存在：

| 枚举 | 用到的成员 | 位置 |
|---|---|---|
| `LaneSignalType` | `Go` / `Stop` / `SafeStop` | SignalOverrideSystem |
| `TrafficLightState` | `Ongoing` / `Changing` | SignalOverrideSystem |

## 二、行为级：编译能过但结果可能不对

### 2.1 `m_Timer` 的语义 ⚠ 最重要

**位置**：[src/Systems/SignalOverrideSystem.cs](../src/Systems/SignalOverrideSystem.cs) `RunProbe()`

**猜了什么**：`TrafficLights.m_Timer` 是累加型计时器，压到 0 就不会切相位。

**确认的部分**：字段存在，类型是 `byte`。

**没确认的部分**：它到底是累加还是倒计时，阈值在哪，以及原版 system 是否每帧都会覆盖我们的写入。

**怎么验证**：M1 探针。日志里 `timer=43->0` 这段能直接看出写入有没有落下去。

### 2.2 帧到秒的换算

**位置**：`SignalOverrideSystem.kFramesPerSecond = 60f`

**猜了什么**：我们的 system 每帧跑一次，60 帧等于一秒游戏时间。

**风险**：CS2 的模拟帧率、游戏速度倍率、`SystemUpdatePhase.GameSimulation` 的实际调用频率都可能不是这个。

**猜错的表现**：相位时长整体偏快或偏慢固定倍数。好消息是这是**单一常数**，测出来实际比例改一个数就行。

**怎么测**：应用一个方案，用秒表量一个相位的实际时长，和 `targetDuration` 比。

### 2.3 方位角假定 +Z 为北

**位置**：`IntersectionScanner.ComputeBearing()`

**猜错的表现**：方位名（N/E/S/W）整体旋转或镜像。不影响功能正确性（程序以 approach 下标为准），只影响 AI 和你看到的描述是否符合直觉。

**怎么测**：导出快照，对照游戏里指北针看某个路口的进口方位对不对。

### 2.4 `LaneFlow` 四桶的含义

**位置**：`IntersectionScanner.ScanFlow()`

**猜了什么**：`m_Distance` / `m_Duration` 是 float4，四个时间桶的累计量，直接求和后相除得平均速度。

**TLE 的做法不同**：它用 `math.lerp(m_Distance, m_Next.y, timeFactors)` 做插值，再和上一次采样**差分**，得到的是瞬时流量。我做的是累计平均，语义不一样。

**后果**：我算出的 `avgSpeed` 是这条车道的历史平均，不是当前时段的。作为拥堵指标偏钝。

**改进方向**：如果导出的 congestion 明显不随时段变化，就改成 TLE 的差分方式（需要保存上一次采样，参考 `CustomStateMachine.CalculateFlow`）。

### 2.5 原版是否会覆盖我们写的 `LaneSignal`

**猜了什么**：把路口从原版 query 排除后，就没有别的系统会改这些 `LaneSignal` 了。

**风险**：`TrafficLightInitializationSystem`（见 1.1 附注）和寻路系统都可能碰它。

**猜错的表现**：应用方案后灯的行为和方案对不上，或者闪烁。

### 2.6 `MasterLane` 跳过是否正确

**位置**：`IntersectionScanner` 里 `if (m_MasterLane.HasComponent(sub)) continue;`

**依据**：抄自 TLE，它这么做是为了避免重复计数。

**猜错的表现**：车道数统计偏多或偏少。对照游戏里实际看到的车道数即可发现。

### 2.7 行人相位策略

**位置**：`SignalOverrideSystem.PedestrianAllowed()`

**当前策略**：本进口机动车全部禁行时才给行人绿灯。这是保守做法。

**后果**：如果任何相位都放行了本进口的车，行人**永远不会**有绿灯，人行道会堵死。

**这是个真实的设计缺陷**，规则引擎生成的方案里每个进口都会在某个相位被放行，所以行人可能一直是红灯。需要在验证后重新设计——可能要给行人单独的相位。

## 三、尚未实现

- **M6 游戏内 UI 面板**：还没做。目前所有功能都通过 Options 设置页的按钮触发，功能是完整的，只是不够好用。UI 工程模板可以抄 `_reference/TLEFrontend`（React 18 + TS + webpack，官方模板产物）。
- **选中指定路口**：没做 ToolSystem（射线拾取复杂度高）。目前用「全城最堵的那个路口」作为操作目标，实用但不能指哪打哪。
- **物理禁转**：目前的转向禁止是**信号级**的（某转向不出现在任何相位里，即永久红灯），车辆仍会规划走这条路然后堵住。真正的物理禁转要改车道拓扑，需要介入 `Game.Net.LaneSystem`——注意 `CommonLibraries/LaneSystem/C2VMPatchedLaneSystem.cs` 声明在 `namespace Game.Net` 且是空实现，说明 TLE 用了某种替换手法，值得研究。另外 `CarLaneFlags.Forbidden` 这个标志位可能是条捷径，没验证过。
- **存档兼容**：`ControlledSignal` 故意不序列化（安全网），但 `SignalPhase` / `LaneRole` / `SignalRuntime` 实现了 `ISerializable`。这意味着读档后相位数据还在但接管标记没了，状态不一致。需要决定：要么都不存，要么都存。

## 五、架构决策备忘

新会话可能会想「为什么这么写」，这里记下理由，避免推倒重来：

- **不用 Harmony**：游戏大量代码经 Burst 编译成非托管代码，Harmony 只能 patch 托管代码。用 ECS query 过滤更干净。
- **不用官方 Anthropic C# SDK**：模组是 net48 + Unity Mono，引 NuGet 依赖要连一串 DLL 一起分发，容易和游戏自带程序集冲突。游戏已带 Newtonsoft.Json，裸 HTTP 依赖最少。
- **API key 从文件读**：不该出现在会被截图的设置界面上，设置文件也可能被同步备份。
- **配时和转向禁止统一成相位掩码**：某转向不出现在任何相位里就等于被禁，这是交通工程里用信号实现禁左的标准做法，不需要改车道拓扑。
- **保留规则引擎**：它是 AI 的对照组。一期的核心问题「AI 到底比规则强在哪」只有在输出可比时才回答得了。
- **AI 请求走后台线程 + 队列**：`EntityManager` 只能在主线程碰，绝不能在 Unity 主线程上阻塞等网络。
